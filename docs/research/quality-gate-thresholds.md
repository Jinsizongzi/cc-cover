密度与时长呈弱负相关（Spearman ≈ −0.31）：短视频密度反而略高（<5 分钟样本中位 343 vs >20 分钟样本中位 301）。

## 评估

1. 当前 error 阈值（密度 30–1200、长度比 0.45–2.20、重复 >4、最少段数 max(3, minutes*5)）在本语料上全部远离边界，实际是「防灾难」下限：只在静音/音乐/严重幻觉时才会拦截。这与「宁可漏报、不可误伤」的定位一致，但不要指望它抓出质量问题。
2. 真正的质量缺口是没有置信度门禁：真实产物中出现 `avg_logprob=-4.18` 的幻觉段，未被任何指标捕获（当前未写入输出只是因为写回源是 FunASR）。建议把 faster-whisper 的平均/最低 `avg_logprob`、`no_speech_prob` 上限纳入审计与告警。
3. 若未来收紧阈值，需要按时长分桶：短视频与长视频的密度分布不同（当前数据中 159–395 的区间远小于 30–1200 的拦截带）。

## 建议

- error 阈值保持宽松（防灾难），但把告警带收紧：密度 <100 或 >600 告警；长度比 <0.80 或 >1.40 告警；连续重复 >3 告警。
- 增加置信度指标（`avg_logprob` / `no_speech_prob`）并纳入 high_risk 汇总。
- `high_risk` 冲突审计纳入「告警 + 写回后报告」，是否硬拦截交给 G4 决策。
- 对 <60s 或 >3h 的极端时长单独定阈值，避免未来收紧时误伤。
